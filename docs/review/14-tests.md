## Real bugs found in the copy, and what was done
1. **Fixed: Wren's bed could never start (app.js `bedState`).** The 0.6 s wait used one `bedNear.stamp` shared by all four beds. A bed drawn after another in the same frame got a dt of about 0. At 390 px wide, bed1 (the one by the way in) is drawn last, and the stay beside it never began. Each bed now has its own clock, and gymtest times all four.
2. **Fixed: chamber lamps shared one clock (`clStamp`).** This is the same class of bug: a lamp drawn after another unkept lamp on screen gets no time. In normal play the climb order hides it. Each lamp now has its own clock. **The shipped game has the same shared `clStamp` (src/world/app.js 897). It is not fixed there.**
3. **Fixed: Tide Shore's returned row was placed beside the moored knot** (26,17 and 26,16). Package W's road weighting pulled both of the zone's things onto the same boardwalk tiles, so two meetings became one heap. `addSpot` now keeps a zone's `z-` things 6 tiles apart, and the returned row is placed first. They are at (26,16) and (26,22), and zonespottest still passes.
4. **Fixed: the Arena ladder was never saved.** `state.arena` (`step`, `day`) is missing from the save record, so a reload put the climb back to step 0. The copy now saves it, with a default of step 0, and roundtriptest pins it. **The shipped game has the same bug (src/world/base.js save list). It is not fixed there**, and it breaks rule 3 for any player who has climbed the ladder.
5. **Superseded: three seal lines told the old level gates** ("Frost Peaks opens at level 3" and others). They were removed here, then replaced by the words pass on rebase.
6. **Recorded, not fixed: the map card for Frost Peaks says "The gate is shut" at one seal** (`placeCard` uses `gateOpen('frost')`, the town's north gate, which needs 2). At one seal Frost Peaks can already be walked into through the Pass, so a player standing there cannot travel back to it. Dan should decide whether a zone you have walked into opens for travel.
7. **Recorded: the clock is in several snapshots.** On the copy, the music tests print `<id>@dusk` (18 to 21 h) by the real hour, as p14's weather did by the real day. The shipped build may do the same with `@night` after 21 h; this was not checked. The fix is to pin `window.__tod` in those tests.
