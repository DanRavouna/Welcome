# Critter Roll: what the current engine consists of, and what it taught

Survey of `/home/user/critter-roll` (Nov 2026). Everything below is from reading the files named; "not checked" marks what I did not read.

## 0. Numbers first

- **Source** (`src/world/`): 18 JS/HTML pieces, 9,067 lines, concatenated by `src/build2.py` (45 lines) into `games/critter-roll/index.html` = **824 KB** (plus `vendor/supabase-2.118.0.js`, 218 KB, pinned from npm). The root `index.html` (7.8 KB) is the "shelf" page listing games.
- Per file (lines / bytes): `app.js` 1585 / 168 KB; `world.js` 1309 / 151 KB; `base.js` 1085 / 76 KB; `adventure.js` 579 / 72 KB; `screen.html` 462 / 47 KB; `action.js` 452 / 57 KB; `game.js` 430 / 32 KB; `shell.html` 420 / 48 KB (23 KB of it CSS); `pxworld.js` 410 / 54 KB; `cloud.js` 234; `data.js` 166; `music.js` 160; `vfx.js` 141; `weather.js` 139; `pixel.js` 124; `ambient.js` 107; `landmarks.js` 106; `runtime.js` 97; `flavor.js` 57. `logic.js` (962 lines), `critter.html`, `helmet.html`, `build.py`, `reassemble.py` are dead leftovers (not checked further).
- **Content, measured by loading the world modules in node**: 61 maps (41 outdoor/dungeon, 20 interiors), 42,896 tiles, 249 interactive objects, 56 signs, 45 placed props, 4 route networks, 9 landmark defs, 7 dungeon/hall layouts, 93 object art routines, 8 ambient critter kinds, 41 palettes, 7 weather kinds, 17 music tracks (+10 derived `@night`), 49 NPC entries with about 300 dialogue strings in `app.js`.
- **Tests**: 103 `.py` files (4,512 lines); 88 run in a full `bash src/run-tests.sh` (world 54, battle 11, saves 14, ui 9, smoke 28; the handoff says 78, the runner's dedup list now yields 88). 89 snapshots, 31 with exact numbers (`exact.txt`). 262 `check()` calls in 19 tests; the older tests only print. 748 `wait_for_timeout` calls. Timing per the runner/handoff: `@smoke` about 30 s; full suite about 4.5 min at 6 jobs on 4 cores (1,100 s summed, 480 s of it sleeps); `snap-build.sh` = three full runs. 10 balance simulators (`duelsim.py`, `towersim.py`, ...) run by hand; `supatest.py` hits live Supabase, separate.
- 20 `window.__*` test hooks ship in the game (`__tod`, `__weather`, `__wind`, `__noTransition`, `__noFollower`, `__duel`, `__towerCurve`, `__zoom`, `__saveFrozen`, `__EDITOR`, ...).

## 1. The DATA the game runs on

**Format reality: almost everything is JS object literals inside the module that consumes it.** The only true data file is `src/world/mapedits.json`, and it is currently `{}`.

| Data | Where | Format | Hand-over-able today? |
|---|---|---|---|
| Tile maps | `world.js` `buildTown/buildZone/buildCity/buildWild/buildAscent/buildDescent/buildInterior`; dungeons in `adventure.js` `sealedArch()` etc. | Generated at load into `{id, name, W, H, grid: char[][], places, signs, objects, exits, arrive, spawn, theme, types, rate}`; single-char tiles (`. , = W Z ~ T R F C G O X` outdoors), `SOLID` set at `world.js:4` | **No**: a map is a procedure plus seed. The *result* is a plain char grid an importer could accept. `mapedits.json` (`{mapId:{cells:[[x,y,'T']]}}`, `applyMapEdits`) is the one seam, limited to terrain chars `.,=WZ~TRFC`. |
| Zones, cities, routes | `world.js` `ZONES`, `CITY_CFG` (path/shop/house rects, roofs, house and sign texts), `NETS` (per route: maps with `hub/doors/nooks/rare/grass/objects/signs`, `links`, `props`, `posts`) | Declarative JS literals with seeds | **Nearly**: data in shape, liftable to JSON; but they are *specs for a generator*, not maps. |
| Palettes / themes | `pxworld.js` `PAL` (per-map colour keys, `arch` style), `world.js` `THEMES` (an older second palette with flags `ice/lava/dense/cave`), `ROOM_STYLE`, `EVO_COL`/`TCOL` | Hex-string literals | **Yes**, but duplicated: two palette tables per map. |
| Landmark props | `landmarks.js` `LAND.defs` | `{w, h, foot, text, draw(g,X,Y,P,k)}`: footprint and text are data, the picture is fillRect code; `camp`/`tent`/`wreck` use ASCII rows + colour map | Footprint/text yes; art only for the ASCII-row ones. |
| Tiles, trees, buildings, player | `pxworld.js` `TREE/ROCK/TUFT/FLOWER/HEAD_D` ASCII rows; `terrain()` paints tiles procedurally; `place()`, `drawHouse`, `gymRoof`, `MARK` draw buildings in code; `frames()` builds 8 facings x 3 frames from ASCII rows | ASCII rows are data; buildings and tile texture are code | Rows yes, buildings no. |
| Dungeon object art | `adventure.js` `ART` (93 routines), `LIGHT` | Code (fillRect on 2 px steps, animated by `t`) | No. |
| Critters | `base.js` `make(seed, stage)` (lines 138-351): element table with move names, rarity weights, stats, natures, `shapes()` (CSS border-radius strings), head/tail parts, `evoKit` + `data.js` `EVO_FEAT/EVO_WING/EVO_PLAN`; `speciesName()` = type prefix + shape suffix (48 = 8 x 6); `SECRETS` are four hand-written species | A seeded **CSS geometry** (`{parts:[{x,y,w,h,r,rot,bg}], body, belly, eyes, mouth, fx}`) rendered both as DOM (`tpl-critter` in `shell.html`) and rasterised (`pixel.js`) | Partly: `EVO_FEAT`, `SECRETS`, colours, move names are data. The species are a procedure; nobody can hand over "critter #17". |
| NPCs and dialogue | `app.js` `npcList()` (lines 532-764): 49 people as `{id, name, x, y, kind, pal, lines/intro/winLine/beatenLines/afterLines/ask/thanks, types, size, stage, pick, lv, reward, ladder...}`; `SCAFFOLD`/`LETGO`; `flavor.js` `OUT/IN/NPC`; `adventure.js` `CLUES`, `STATUE_TEXT`, object `text`; `CITY_CFG` texts | Literals with a few closures (`progress: (g) => ...`) | **Yes, mostly**: JSON-able once the closures become named rules. Flavor lines already are. |
| Quests | `base.js` `questDefs()/makeQuests()`, `data.js` `CITY_QUESTS` (`see/keep/beat`), `badgeChecks`, `TITLES` (with `of: (s)=>...` closures) | Data with closures | Partly. |
| Items, economy, balance | `data.js`: `KEEP_COST`, `GATES`, `ROUTE_GATES`, `ITEM_FX`, `TOWER`, `TOWER_CURVE`, `TWISTS`, `DUEL_HP/DMG/PACE`, `DUEL_TUNE`, `ACT_XP`, `SHINY_ODDS`, `MAP_LAYOUT`, `LEADERS`, `ABILITIES` (text only; numbers live in `Component.hit`) | Pure constants | **Yes**: the closest thing to a designer tuning sheet. |
| Music | `music.js` `T` | Per track `bpm, wave, duty, chords, bass, drums, lead` as text (`'E5 - G5 - C6 ...'`, 8 bars x 8 steps); `NIGHT_LEAD` | **Yes**: a tracker-like text a composer could edit. |
| Sound effects | `base.js` `sfx()` | `{tap:[[880,0.04]], ...}` | Yes (tiny). |
| Weather, ambient, wind | `weather.js` `KINDS/CLIMATE/ROUTE_MIX/REGION`; `ambient.js` `BY_REGION/MAP_LIST` counts and `defs` (code); `world.js` `WINDS` | Weights and counts are data; drawing is code | Weights yes. |
| Save | `localStorage` `critter-roll:v2` (game state), `:world` (position, written every second), `:id`, `:tip`, `:meta`, `:menu`, `:dev`, `:device` | JSON; `Component.update()` merges over the old record so unknown fields survive | n/a |

In short: **the only designer seam today is `mapedits.json`, plus informally `data.js`, `music.js` and the `npcList()` literal.** Every picture (except ASCII rows), every map shape and every critter is a program.

## 2. The GENERATORS

**Pixel sprites from geometry (`pixel.js` PIX).** Input: a critter object from `make()` and a facing. `geometry()` re-arranges the same parts per facing (`FACE` table: back = mirrored, no face, tail in front; profile = body x0.8, one eye; quarters x0.92), `draw()` paints canvas paths at scale 0.25 (`big`) or 0.075 (`icon`), then a pixel pass: alpha threshold, 2-tone edge shading, outline, icon posterisation, mythic sparkles; cached by `seed:stage:mode:facing`. Output: PNG data URL. **To replace**: a sprite-sheet lookup keyed on `(species, stage, facing, mode)` at `PIX.sprite()`; the game already addresses critters by `speciesNo` (1-48) plus stage, so 48 x 3 x 5 drawings (mirroring the rest) is the whole bill. Seed-level colour variation would be lost unless the artist supplies tints.

**World tiles, buildings, people (`pxworld.js` PXW).** Input: a map grid plus a palette id. `terrain()` paints a 16 px/tile canvas (shown at 2x) procedurally: ground noise, path edges, water, tufts, flowers, trees from `TREE` rows; it records animated items so `bake()` can render 6 wind poses with `swayStamp` (only edge pixels move 1 px). `place()`/`drawHouse` draw buildings from `places[]` rects and the palette's `arch` style (cottage/longhouse/forge/shell/grove), with `MARK` symbols instead of names. `frames(pal)` builds 24 player canvases from ASCII rows, recoloured per NPC by `pal`. **To replace**: a tileset with autotile edges for `=` and `~`, tree/rock/tuft sprites, building sprites keyed by `arch` and size, and a 16x20 character sheet (8 facings x 3 frames; one sheet per body type, palette swaps kept). Wind baking assumes it can find edge pixels; with hand sprites, hand over the 6 poses or keep the flutter as a post-process.

**Landmarks (`landmarks.js` LAND) and dungeon objects (`adventure.js` ART).** Input: def id, tile position, palette, a 0..1 variation `k`; output: pixels onto the terrain (props) or per frame with state (`ART[kind](g, x, y, st, t, o)`: braziers' `burn`, lamps' `lit`). Placement is already data (`PROPS`; `addProp` searches outward from a hint tile for a legal footprint and plants a signpost). **To replace**: a sprite per def plus the existing `foot` string, a small frame set keyed on state for stateful objects; `LIGHT` stays as data.

**Maps (`world.js`).** Input: seeds and specs. Seven generators: `buildTown` (hand-placed rects over a seeded tree border), `buildZone`, `buildCity(CITY_CFG)`, `buildWild(spec)` (hub + doors + nooks, winding 2-wide paths, `prot` mask), `buildAscent/buildDescent` (the descent is the ascent flipped), `buildDungeon` (takes `ADV.DUNGEONS[id]()` rows strings and objects: the one hand-made layout, written as code that fills rows), `buildInterior` (12x9 rooms from `ROOM_LAYOUTS` or `CITY_ROOMS`). Links are `connect()/linkEdge()` edge+offset pairs; `nextHop()` BFSes exits for the objective arrow. Then a tail of post-fixes (gym doors, the Arch plaque, gates cut into palisades), and `applyMapEdits()` last. **To replace**: an importer (Tiled JSON, or `mapedits.json` extended to whole grids plus `places/objects/signs/exits/npcs` layers) that emits the same `MAPS[id]` object; `buildDungeon` shows that rows-of-chars + objects + spawn/exit already suffices. Keep the generators' hidden contracts as *validators*: 2-wide paths, reachability of every door and nook (`wildtest`), a rare patch per route, props off borders and the trainer sight line (`PROP_RESERVED`).

**Music (`music.js`).** `compile()` turns the track text into 64 step events; `tick()` schedules WebAudio oscillators 150 ms ahead (pulse via `PeriodicWave`, triangle bass, noise drums). Night variants are derived (bpm x0.78, triangle, no drums). `_render()` renders offline for `musictest`. **To replace**: swap `play(id)` for decoded buffers; the crossfade (`startTrack` 0.5 s out / 0.6 s in), unlock-on-first-gesture and visibility pause are the reusable parts.

**Weather / ambient / wind.** `WEATHER.at(mapId, date)` hashes `date + 6-hour block + region` against `CLIMATE` weights (deterministic across devices, nothing saved). `AMBIENT` spawns `[kind, count]` per region with a seeded RNG; each def has `tile/when/make/step/draw`. Wind: `WINDS` per region (the cold is 0 by design), `windLevel()` is pure, `windNow()` integrates a phase that selects one of 6 baked poses. All three already separate data from behaviour; only the drawings are code.

**Critters (`base.js make()`).** Input: integer seed (1..999,999; `SECRETS` above), stage, level. One seeded RNG picks element, rarity, stats, nature, body, shape, head, tail, colour shifts; `evoKit` adds limbs/wings/crest from `EVO_FEAT` and `EVO_PLAN`. **To replace**: keep seed → (species, rarity, stats, nature, shiny) as the data generator, and route the look through hand assets keyed by species and stage. `roundtriptest` and `evotest` pin that seeds keep their identity; `make(seed)` must stay stable for old saves.

## 3. The RUNTIME core: engine vs. game

**Lifts cleanly (game-independent now):**
- `runtime.js` TPL (97 lines): compile HTML with `sc-if`, `sc-for`, `dc-import`, `{{holes}}` and `on*` handler holes; `mount()` returns a `render()` that rebuilds and *morphs* the live DOM (`morph`/`syncAttrs`, input focus preserved). A tiny declarative UI runtime with no Critter Roll knowledge. `screen.html` (62 `sc-if`, 32 `sc-for`) is written against it; `renderVals()` in `game.js`/`base.js` is the view-model.
- `cloud.js` CLOUD: local-first sync with hash + `savedAt/syncedAt` meta, debounce 3 s, lease (`acquire_save_lease`, 4 s TTL) + re-read before write, conflict dialog hooks, dual backend (claude.ai `window.claude.use('db')` or Supabase email/password). Game-specific only in `KEYS` (the four save keys) and `progress()` (what counts as progress). Reusable as-is with those two injected. `supabase/001_saves.sql` not read.
- `pixel.js` rasteriser, `vfx.js` (slash/impact frame sets, particles, shake, hit-stop), `music.js` scheduler, the `weather.js`/`ambient.js` frameworks, `PXW.frames()`, the `LAND` prop system, and `WORLD`'s movement/collision (`collides`, 18x8 px box), pixel-snapped camera, 8-way facing, transition (`go/stepTR/transitionFx`), darkness rings (`drawDark`), exit BFS (`nextHop`) and the input abstraction (`WORLD.input.jx/jy` + `step(dt)`) that bots drive.
- Test plumbing (section 4) and the build (section 5).

**Tangled with Critter Roll:**
- `base.js` `Component` is the original 2025 canvas game ported wholesale: critter generation, battle math (`hit/act/resolve/endRound`), quests, badges, sfx, and the save write (`update()` lists every field by name at line 94: the "never drop a field" rule is a hand-maintained list). `Base.setState` calls `APP.schedule()` directly: the model knows the view.
- `game.js` `Game` adds levels, party, Tower, city quests, action rewards; `renderVals()` is the screen view-model.
- `app.js` APP (1585 lines) is HUD + menus + dialogue + shop/party/bag + world map + backup codes + account panel + hints + every adventure state machine (Lamp Tower levers, the four gym trials `tending/BED_STAGE_S`, `iceCells/STILL_S`, `burn/BURN_S`, `coral/CORAL_SEQ`, the Forge, the Long Watch, the pouch, fishing) + dev tools + `npcList()` content. Rendering here is string `innerHTML`, not TPL. The trial state machines are the game's heart and would stay game code anywhere, but they call `WORLD.setTiles/setGate/openTiles`, `ADV.LIGHT`, `objState`: those hooks are the engine API that emerged.
- `world.js` mixes the engine (movement, drawing, wind) with all content generation in one 1,309-line IIFE; `WORLD.init(canvas, opts)` takes 15+ callbacks (`onInteract, onNear, onEncounter, npcs, tint, objState, carry, relit, homeLit, weather, still, ambient, exitLocked, onAlert...`): the real engine/game boundary, undocumented but explicit.
- `action.js` ACT reuses `Game.hit()/endRound()`; enemy `BEH` per element and the eight type verbs are content written as code.

## 4. The TEST DISCIPLINE as an engine feature

What exists and what it buys:
- **Bots with real defaults.** `openingtest.py` runs without the seed hook: title → light → Fern → starter → BFS over the real grid → walks in real time with `WORLD.input` → fights with `ACT.attack()` until an orb drops → Keep, all timed. `walktest.py` and `src/walk.js` BFS over `WORLD.solidAt` then drive `W.step(1/60)`, so collision boxes, not tile lists, are proven. `wplay.py` plays with real randomness. Engine dependency: only `WORLD.pos/solidAt/input/step/nearest/enter/setPos` and `APP.dialog/advance`. The bot is generic; the goals are game.
- **Real-time rhythm tests.** `windrhythmtest.py` logs `WORLD.windFrame()` per rAF against `performance.now()` for 12 s and asserts pose steps per second ≤ wind pace, no jumps; `facingtest.py` samples `WORLD.walkFrame()` every 50 ms while walking; `verbtest.py` samples `ACT.verb().r` growth over 1.5 s. Needs only "expose the current pose number as a function". Stills hide speed-ups and stalls: this is the lesson.
- **Meaning lint.** `telltest.py` pulls every NPC line, object and prop text from the live game (`WORLD.allNpcs()`, `MAPS[].objects/props`) and regex-checks for recited rules (`TELL`) and tips (`TIP`), with a leader allowlist. The mechanism is generic; the regexes are this game's voice.
- **Snapshots with masked numbers** (`snapcmp.py`): snapshot = lines printed in all of three runs; compare = every snapshot line must still appear; numbers masked to `#` except for `exact.txt` tests; normalisers for date, weather words, `@night`, daily quest, tips, `own:` flags. Runner: one retry, `FLAKY` label, `SUMMARY` with exit code, per-test `.snapdiff`. Game-independent except the normaliser list.
- **Mutation checks.** Done by hand twice (handoff): inject five bugs, see what goes red; the gaps were closed with `balancetest.py` (pins `DUEL_HP` etc. and the leaders' exact seal sentences) and `roundtriptest.py` (writes every top-level save field with a distinct value, reloads, compares; pins the Dex count). Lesson recorded: "a snapshot proves 'still prints what it printed'; anything that matters as a number or a sentence needs a `check()`."
- **Seed hook** (`pwhook/sitecustomize.py`): monkeypatches Playwright's `new_context` to inject an existing-player save and `__noTransition`; the hook-free test list is hard-coded in `run-tests.sh`.
- **Sims**: `duelsim.py` runs the real `ACT` code at simulated speed with two bot styles; `data.js` constants cite which sim tuned them.
- Weak spots the handoff names itself: `guidetest`'s pixel check proves little; the fixed sleeps; most old tests print rather than assert; feel, tempo and video cannot be judged from here.

## 5. BUILD and deploy

`build2.py`: read `shell.html`, replace `/*@@JS@@*/` with 18 files concatenated in a fixed order (`mapedits.json` wrapped as `const MAPEDITS`), replace `<!--@@SCREEN@@-->` with `screen.html`, write one file. No bundler, no modules: globals (`TPL, PIX, LAND, ADV, PXW, WEATHER, AMBIENT, WORLD, VFX, ACT, CLOUD, MUSIC, FLAVOR, Base/Component, Game, APP`) in load order. `pages.yml` copies root `index.html` + `games/` to Pages on push (the built file is committed). `mapedits.yml` rebuilds + `@smoke` + commits + triggers Pages when `mapedits.json` changes (the editor, on another branch, pushes it; not checked). Vendored Supabase with `onerror` fallback to local saves. Test paths assume the old sandbox (`/mnt/user-data/outputs/...`), bridged by `test-setup.sh` symlinks. **Reusable**: the single-file, committed-build shape and the "data file change → CI rebuild → smoke → deploy" loop, which is exactly what a designer-assets workflow needs once generalised from one JSON to a folder. **Accidental**: global ordering, the sandbox paths, two palettes, test hooks shipped to players.

## 6. Judgement: load-bearing vs. accidents

Load-bearing for how this game got made (keep in the new engine):
1. **The runtime hooks that tests and bots drive**: `WORLD.input` + `step(dt)`, `pos/solidAt/nearest/enter/setPos`, pose-number getters (`windFrame`, `walkFrame`, `ACT.verb()`), `APP.dialog/advance`, `window.__tod/__weather/__wind`. Without these no bot or rhythm test exists. Design them in from day one as a documented test API, not ad-hoc globals.
2. **Snapshot + masked numbers + retry + `check()`**, and the mutation habit: cheap, generic, and the only reason an AI could change 9,000 lines daily without a human playing.
3. **Everything as data in the end**: `MAPS[id]` char grids with `places/objects/signs/exits`, `ADV.DUNGEONS` rows strings, `NETS/CITY_CFG` specs, `data.js`, `music.js` text, `npcList()`, `flavor.js`, `mapedits.json`. The formats are right; they just live in JS. Reading them from files is a small step.
4. **The meaning lint** and the "Meaning:" comment convention (43 occurrences in `src/world/*.js`). Make it a first-class content field, not a comment.
5. **Local-first save with field-preserving merge and cloud reconcile** (`Component.update`, `cloud.js`): rule 3 of CLAUDE.md held because of this.
6. **The single-file, committed-build, CI-rebuild-on-data-change** shape.
7. **Declarative screens via TPL + `renderVals()`**; the `innerHTML` strings in `app.js` are the part that did not scale.

Accidents of this game (do not carry over as structure):
- Procedural art and maps as the *source of truth*. They existed because there was no artist; they made every visual change a code change and forced two palette tables. With Dan drawing, the generators become validators and placement helpers (`addProp`'s footprint search, route reachability).
- Critters as CSS geometry rendered twice (DOM and canvas): a remnant of the 2025 DOM game; `pixel.js` is a bridge, not a plan.
- `app.js` holding UI, trial state machines and NPC content; `world.js` holding engine and world content; the `Base.setState → APP.schedule` coupling.
- The hand-maintained save field list; the hook-free test list in the runner; the sandbox paths; the fixed sleeps; test hooks shipped in production.
- Seeds as identity (species = type x shape): fine here, but a new engine should separate "identity for saves" from "how it was generated".

Not checked: `docs/handoff-archive.md` body, `supabase/001_saves.sql`, the map-editor branch, `perf.py` and most older print-only tests beyond their headers, the shell CSS in detail, `logic.js`/`critter.html` leftovers, and whether the "78 tests" figure or the 88 the runner now lists is current in Dan's mind.
