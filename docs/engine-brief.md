# The engine: brief (v1, from Dan's answers, Nov 7 2026)

Status: decisions, not a design. Drafted one question at a time after `docs/process.md`. Nothing is built. The design and the first milestone come after Dan has read and corrected this.

## What it is

The engine is **the studio and the player in one**: the environment where Dan makes the art, the maps, the sounds and the events of a game, and the thing that plays the games on the shelf. It serves the process in `docs/process.md`: a station is filled, Dan makes a grey box, the AI builds the act with placeholders, Dan plays, Dan replaces the placeholders in the same environment.

## Decisions

1. **Scope grows game by game.** The engine supports whatever the first game's stations need, and kinds of play are added as later games need them. No genre list up front. (Critter Roll's engine was one genre with everything in it.)

2. **One shared engine file, games as data.** The site serves one engine script; each game is a folder of data and assets the shelf loads into it. One place to fix the engine; a game is content only.

3. **The grey box is drawn in the studio, in the browser, on the phone.** Dan paints tiles, places people and doors, and writes the intent and what happens in a box. The station is saved as data the engine reads.

4. **The studio is also a pixel art editor with animation**, generating tiles, sprites and props. The engine is the environment where the art is made, not an importer of files from elsewhere.

5. **Sound is made in the same environment** (a small tracker or step sequencer played by the engine's synth). If that does not work in practice, audio files from outside are the fallback.

6. **Events are step cards** in the studio: say, choice, set flag, if, move, wait, set tile, sound, and so on, as cards with fields and no syntax. Small by design; the AI adds step kinds as stations need them.

7. **The road lives in the studio, but is optional.** The sentence, the last act and the stations (meaning, hint, act) are entries in the studio and content can hang off a station, but a map can be made without one. The road is a view, not a gate. (The process says nothing is built before its station is filled; the engine does not enforce it.)

8. **Fresh code, old ideas.** Nothing is copied from Critter Roll. What the old code taught is kept as design: the test API that bots drive (input vector, step, position, solidity, nearest, a pose number per animated thing, dialogue advance), everything as data with a JSON round-trip test, the field-preserving save merge, snapshots with masked numbers and a flaky retry, the meaning lint, a data change triggering rebuild, smoke test and deploy.

9. **The studio runs on the site, behind a sign-in**, usable by one specific account (Dan's email). Its door is a secret cartridge slot at the bottom of the shelf. The email check in the page is only the door; the real protection is the server rule that only that user can write studio data and publish.

10. **Cloud saves from the start, one account for the shelf.** One sign-in on the shelf; every game's save follows the player. Same shape as Critter Roll (local-first, debounced push, lease, conflict dialog), built fresh.

11. **Tile size is set per game.** The engine takes the grid from the game's data; the first game decides its own.

12. **Published content lives in the repo, pushed by the studio.** Publish writes the game's data and assets to GitHub; a workflow rebuilds, smoke-tests and deploys; content is versioned with the code. This morning's attempt failed because a private claude.ai page had no GitHub connector. On the site the push can go through a small server function (Supabase Edge Function) that holds a GitHub token as a secret, checks that the caller is Dan's account, and commits; the token never reaches the browser or the repo. Drafts in progress live in the database until published.

## What follows from them (the AI's reading, to correct)

- The studio is three editors and a player sharing one data model: map, pixel (with animation), sound, events; the road as a fourth, optional, view; the engine runs inside the studio so a station can be played from the tile you tap.
- The data model is the first design task: game, road, station, map, tileset, sprite, animation, palette, sound, track, person, event script, flags. Every item survives a JSON round trip and holds no code.
- The engine ships a test API from day one, used by the AI's bots before a station reaches Dan (process rule 5), and by Dan's own Play button in the studio.
- Placeholders are generated by the engine (grey tiles, a stand-in body, a synth tune) and are the only generated thing; replacing one is an edit in the same studio.
- The shelf stays as it is: number, name, year, record. It gains one hidden slot.
